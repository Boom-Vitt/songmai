# คำสั่งสร้าง HANDOFF.md

ใช้ในแชตเดิมก่อนเปลี่ยน agent โดยแนบ SKILL.md และเทมเพลต หรือให้ local agent อ่านไฟล์เหล่านี้:

```text
ช่วยสร้าง HANDOFF.md ตาม Songmai สำหรับส่งงานนี้ให้ agent ตัวถัดไป
อ่านคำขอล่าสุดและ workspace จริง แล้วใช้เทมเพลตของ Skill
เก็บเป้าหมาย เกณฑ์เสร็จ ขอบเขตที่อนุญาต สถานะ git/local edits
สิ่งที่เสร็จพร้อมหลักฐาน การตัดสินใจ ไฟล์อ้างอิง คำสั่งที่รันจริง
ผลตรวจ งานค้างตามลำดับ และข้อมูลที่ยังไม่ทราบ
ใช้ path ไฟล์อ้างอิงแบบ relative ต่อ workspace root และรูปแบบที่ checker รองรับ
ไม่เดาผลทดสอบหรือสถานะที่ไม่ได้ตรวจ ไม่คัดลอกความลับหรือ raw chat log
หลังอัปเดตเอกสารและ commit สุดท้ายที่ได้รับอนุญาตแล้วถ้ามี รัน songmai.py seal
ถ้ามี snapshot เดิม ให้ใช้ --replace หลังตรวจและบันทึกสถานะล่าสุดจริงเท่านั้น
รายงาน HANDOFF.md และ HANDOFF.songmai.json ที่ต้องส่งไปพร้อมไฟล์งาน
รอบนี้สร้างเอกสารส่งต่อและ seal หลักฐานเท่านั้น ยังไม่ทำงานค้างแทน agent ถัดไป
```

ข้อความสุดท้ายจำกัดเฉพาะรอบสร้างเอกสาร ผู้รับยังทำงานเดิมที่เจ้าของอนุญาตค้างไว้ต่อได้ ต้องอ่านคำสั่งจริงและขอบเขตในเทมเพลต

ส่วนอ้างอิงใช้ heading `## ไฟล์อ้างอิง` เพียงหนึ่งครั้งและรายการ `- ` ตามด้วย path ใน backticks หนึ่ง path ต่อบรรทัด คำอธิบายอยู่นอก backticks ห้ามเติม `:12` หรือ `#L12` ต่อ path; ใส่เลขบรรทัดในคำอธิบายแทน

หากงานไม่มีไฟล์ ใช้รายการเดียว `- ไม่มีไฟล์อ้างอิง` ผล PASS จะนับ 0 ไฟล์และไม่ได้พิสูจน์ว่าแนบข้อมูลครบ

ให้ agent ใช้ path จริงของ Skill รัน `python3 "<skill-dir>/scripts/songmai.py" seal HANDOFF.md --root .` หากรันไม่ได้ให้ระบุ `SEAL_NOT_RUN` ไม่สร้าง hash หรือสถานะ Git ด้วยการเดา Snapshot ไม่มีเนื้อหาไฟล์แต่ยังมีรายชื่อไฟล์และชื่อ branch: ตรวจสิ่งที่จะส่งก่อนแนบ

ส่ง snapshot เป็นไฟล์แนบแยก ไม่ใส่ HANDOFF.songmai.json ในส่วนไฟล์อ้างอิงของเอกสารเอง เพราะ snapshot ไม่สามารถ hash ตัวเองได้

เทมเพลตเป็นแบบฟอร์มที่ยังไม่กรอก จึงไม่ควรผ่าน checker จนกว่าจะเปลี่ยน `<relative/path>` เป็นไฟล์จริง
